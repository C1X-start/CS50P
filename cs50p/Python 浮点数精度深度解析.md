# Python 浮点数精度深度解析

> 🔗返回主课：[[CS50P-Lecture 0 变量、字符串与函数基础]]

## 📌本节总览
- 彻底讲透 float 浮点数出现「长串9」「计算不准」的底层原因
- 梳理所有常见的精度陷阱与反直觉现象
- 分场景给出对应解决方案：日常展示、精确计算、相等判断
- 理清 `round()` 舍入规则与浮点数精度的叠加效应

## 📖核心知识点

### 一、为什么会有浮点数精度误差
#### 1. 底层原理：二进制存储限制
计算机内部只能识别二进制（0和1），整数可以用二进制精确表示，但**绝大多数十进制小数，无法用二进制精确表示**。

以 `0.1` 为例：
- 十进制的 0.1，转换成二进制是 **无限循环小数**：`0.00011001100110011...`
- Python 的 float 采用 IEEE 754 双精度标准，只用64位存储空间，只能截断保留近似值
- 这个近似值和真实的 0.1 之间存在极其微小的误差，单次运算不明显，多次累加后误差会放大

> 这不是 Python 的 bug，是所有采用 IEEE 754 标准的编程语言（C、C++、Java、JavaScript 等）的共性问题。

#### 2. 直观验证
```python
# 查看0.1在计算机内部的真实存储值
print(f"{0.1:.20f}")
# 输出：0.10000000000000000555
````

可以看到，我们写的`0.1`，在计算机里并不是严格等于0.1。

### 二、最经典的精度坑：0.1 + 0.2 ≠ 0.3

这是所有编程语言都存在的经典问题：

```
print(0.1 + 0.2)
# 输出：0.30000000000000004

print(0.1 + 0.2 == 0.3)
# 输出：False
```

原因：0.1和0.2各自都有微小误差，相加后误差叠加，结果和0.3的近似值不相等。

### 三、分场景解决方案

#### 场景1：日常展示、输出结果（CS50P习题首选）

**用 f-string 限定小数位数**，只展示需要的精度，自动四舍五入，视觉上和数学结果一致。

```
x = 1.23
y = 1.2
result = x + y
print(f"{result:.2f}")  # 输出 2.43
```

✅ 优点：简单高效，满足绝大多数做题、普通展示场景 ❌ 缺点：只是展示层面的修正，内部存储的数值依然有误差

#### 场景2：高精度要求（财务、金额计算）

使用 Python 内置 `decimal` 模块，用十进制精度进行运算，避免二进制误差。

```
from decimal import Decimal, getcontext

# 设置全局运算精度
getcontext().prec = 20

x = Decimal("1.23")
y = Decimal("1.2")
print(x + y)  # 输出 2.43，完全精确
```

⚠️ 注意：传入的数字必须用**字符串**形式写入，直接写float会先带入误差。 ✅ 优点：完全精确，适合金融、会计等对精度要求极高的场景 ❌ 缺点：运算速度比float慢，写法稍繁琐

#### 场景3：判断两个浮点数是否相等

绝对不要直接用 `==` 判断，使用 `math.isclose()` 允许微小误差。

```
import math

print(math.isclose(0.1 + 0.2, 0.3))
# 输出：True
```

原理：判断两个数的差值是否在允许的极小误差范围内，符合工程实际逻辑。

### 四、round() 与精度的叠加效应

`round()` 本身采用**银行家舍入（五成双）**规则，再叠加浮点数精度误差，结果会更加反直觉。

以你遇到的 `1.2 + 1.3` 为例：

1. 数学上 1.2 + 1.3 = 2.5
2. 浮点数内部计算结果：略小于 2.5
3. `round()` 识别到数值小于2.5，直接向下取整得到 2
4. 即使内部恰好等于2.5，`round(2.5)` 也会取偶数 2，而不是3

```
print(1.2 + 1.3)        # 显示2.5，实际内部略小于2.5
print(round(1.2 + 1.3)) # 输出 2
```

## ❗易错点 & 踩坑记录

1. ⚠️ 不要用 `==` 直接比较两个浮点数是否相等，优先用 `math.isclose()`
2. ⚠️ 不要用 float 直接做金钱计算，会出现分级别的金额误差，推荐用 decimal 或整数（单位改成分）
3. ⚠️ `round(2.5) == 2` 不是bug，是标准的银行家舍入规则
4. ⚠️ 浮点数误差会随着运算次数累加，循环计算一万次后误差会明显变大
5. ⚠️ decimal 模块传入数值必须用字符串，用 float 传入会先丢失精度

## 💻常用验证代码

```
# 1. 查看浮点数内部真实值
print(f"{0.1:.20f}")

# 2. 经典0.1+0.2测试
import math
print(0.1 + 0.2)
print(math.isclose(0.1 + 0.2, 0.3))

# 3. 高精度计算
from decimal import Decimal
print(Decimal("0.1") + Decimal("0.2"))

# 4. round舍入规则测试
print(round(2.5))
print(round(3.5))
```
